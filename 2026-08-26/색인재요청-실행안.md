## A. Google Search Console 재크롤 요청 절차

### A-1. sitemap 재제출

1. Search Console 접속: https://search.google.com/search-console
2. 속성 선택: `utils.minon.kr` (또는 도메인 속성 `minon.kr`)
3. 좌측 메뉴 → **Sitemaps**
4. 기존 sitemap.xml URL(`https://utils.minon.kr/sitemap.xml`) 상태 확인
5. "새 사이트맵 추가" 입력란에 동일 URL 재입력 → **제출** 클릭
6. 상태가 "가져올 수 없음" 뜨면 5~10분 후 재시도

### A-2. 개별 URL 색인 요청 (4회 반복)

각 URL 순차:

1. 좌측 상단 **URL 검사** 클릭
2. 상단 검색바에 대상 URL 붙여넣기 (전체 https 형태)
3. 실시간 검사 완료 대기 (10~30초)
4. 결과 화면에서 **"색인 생성 요청"** 클릭
5. 큐 등록 확인 다이얼로그 → 확인
6. 다음 URL 반복 (총 4회)

**주의**: 속성당 하루 색인 요청 한도 ~10건 · 4건은 여유. 요청 간 대기 시간 불필요.

### A-3. 색인 상태 관찰

- 요청 후 통상 **수 분 ~ 수 일 내** 크롤 실행
- **커버리지** 리포트(좌측 메뉴)에서 색인 반영 상태 확인
- 3~5일 뒤 각 URL "검사됨: 색인이 생성됨" 상태로 전환되는지 관찰
- 미색인 시 URL 검사 재실행 → 크롤 차단 사유 확인

## B. Cloudflare 캐시 퍼지 문안 (실행은 대표 소관)

### B-1. 대시보드 방식 (권장)

1. https://dash.cloudflare.com 접속
2. 도메인 `minon.kr` 선택
3. 좌측 메뉴 → **Caching** → **Configuration**
4. **Purge Cache** 섹션 → **Custom Purge** 선택
5. "URL" 입력란에 아래 붙여넣기 (한 줄당 하나):

```
https://utils.minon.kr/lease-expiry-dday/
https://utils.minon.kr/long-term-care-dday/
https://utils.minon.kr/birth-registration-dday/
https://utils.minon.kr/inheritance-waiver-dday/
```

6. 홈·sitemap 함께 퍼지 (리브랜드 텍스트 반영 정합):

```
https://utils.minon.kr/
https://utils.minon.kr/index.html
https://utils.minon.kr/sitemap.xml
```

7. **Purge** 클릭 → 전 세계 엣지 30초 이내 무효화

### B-2. API 방식 (참고 · 대표 판단)

```
curl -X POST "https://api.cloudflare.com/client/v4/zones/{ZONE_ID}/purge_cache" \
  -H "Authorization: Bearer {API_TOKEN}" \
  -H "Content-Type: application/json" \
  --data '{"files":[
    "https://utils.minon.kr/lease-expiry-dday/",
    "https://utils.minon.kr/long-term-care-dday/",
    "https://utils.minon.kr/birth-registration-dday/",
    "https://utils.minon.kr/inheritance-waiver-dday/",
    "https://utils.minon.kr/",
    "https://utils.minon.kr/sitemap.xml"
  ]}'
```

ZONE_ID·API_TOKEN은 대표 소관 · 이 문서에 노출 X.

## 실행 순서 (권고 · 순서 엄수)

```
1. git push origin main (대표 승인 대기)
     ↓ 30초~2분
2. Cloudflare Pages 자동 배포 완료 확인
     ↓
3. CF 캐시 퍼지 (B-1 대시보드) · 대표 실행
     ↓ 30초 (전 세계 엣지 무효화)
4. GSC sitemap 재제출 (A-1)
     ↓
5. GSC 개별 URL 4건 색인 요청 (A-2)
     ↓ 수 분 ~ 수 일
6. GSC 커버리지 리포트에서 색인 상태 관찰 (A-3)
```

## 순서 근거 짚음

- **push 이전 재크롤 요청 지양** — 크롤러가 구 index.html 텍스트 색인 → 리브랜드 반영 지연 (이번 사이클 스펙 불일치 재발 리스크).
- **캐시 퍼지 없이 재크롤 시 리스크** — Google 크롤러가 CF 캐시된 구 콘텐츠 색인 → 리브랜드 무의미. **퍼지가 재크롤보다 반드시 선행**.
- **A-2 색인 요청은 힌트지 강제 아님** — Google 자체 판단으로 크롤 우선순위 결정. 다만 요청 안 하는 것보다 명확히 빠름 (통상 24~72시간 앞당김).

## 짚음 (마케팅 관점)
