## lease-expiry-dday (임대차 계약 만료 D-day)

### 실황 확인

| 토큰 | 마이클 값 |
|------|-----------|
| `--primary` | `#D97706` (amber-600) |
| `--primary-hover` | `#B45309` (amber-700) |
| `--primary-soft` | `#FEF3C7` (amber-100) |
| `--primary-soft-border` | `#FCD34D` (amber-300) |

- 구조: h1 직접 노출 (h1-row 없음 · 공유버튼 없으므로 정합) → hero-line 존재 ✓
- 광고 2슬롯 (`#ad-slot` · `#ad-slot-bottom`) · SEO·JSON-LD·CF Analytics·Pretendard 완비 ✓
- 4상태: safe(amber soft) · renew(yellow-100 · `#F59E0B`) · danger(red-soft) · expired(muted)
- 갱신청구권 행사 기간(rw-range) + 기간 내 D-day 계산 완결 ✓
- favicon: 🏠 + amber 배경 ✓

### 도메인 분석

임대차 계약 만료를 찾는 사용자의 감정: **불안 + 준비할 시간 인식**. 집이라는 삶의 근거지가 걸린 문제라 "긴박한 예매"보다 "따뜻하고 안정된 경고"의 결이 맞다.

기존 주황 `#EA580C`(orange-600) = "예매·추석" 도메인의 붉은 긴박감.
마이클의 `#D97706`(amber-600) = 황금·온기·계약의 안정감 → 집·부동산 도메인에 정합.

→ 두 색은 도메인이 다르다. 주황 계열이 두 축이 되더라도 분리가 맞다.

### 대비값 검토 — 이슈 있음

| 색 조합 | 대비비 | 판정 |
|---------|-------|------|
| `#D97706` vs `#FFFFFF` (버튼·링크) | ≈ 3.2:1 | **AA 미달** (4.5:1 필요) |
| `#D97706` vs `#F8F9FA` (bg 위 링크) | ≈ 3.0:1 | **AA 미달** |
| `#B45309` vs `#FFFFFF` (hover 색) | ≈ 5.6:1 | **AA 통과** ✓ |

버튼 14px bold는 WCAG 기준 대형 텍스트 미해당(≥18.67px bold 필요) → 4.5:1 기준 적용. `#D97706`은 미달.

기존 `#EA580C`도 대비 ≈ 3.5:1로 비슷한 문제를 안고 있고 팔레트에 수용 중. 일관성 논거는 있으나, 부동산·주거는 사용자 신뢰가 특히 중요한 도메인이라 접근성 리스크를 줄이는 게 낫다.

### 시안

**A안: `#D97706` 현행 유지 (amber-600)**

- 대비 3.2:1 AA 미달이지만 `#EA580C` 수용 원칙과 일관
- 밝고 따뜻한 톤 그대로 유지
- 무수정

**B안: `#B45309` 기준으로 상향 (amber-700) — 달리 권고**

| 토큰 | 변경값 |
|------|--------|
| `--primary` | `#B45309` (amber-700 · 대비 5.6:1 AA 통과) |
| `--primary-hover` | `#92400E` (amber-800) |
| `--primary-soft` | `#FEF3C7` 유지 (amber-100) |
| `--primary-soft-border` | `#FCD34D` 유지 (amber-300) |

"따뜻한 안정감"은 amber-700에서도 충분히 살아 있다. 대비 확보가 더 중요하다.

## long-term-care-dday (노인장기요양보험 신청 D-day)

### 실황 확인

| 토큰 | 마이클 값 | 비고 |
|------|-----------|------|
| `--primary` | `#0F766E` (teal-700) | |
| `--primary-hover` | `#115E59` (teal-800) | |
| `--primary-soft` | `#CCFBF1` (teal-100) | |
| `--primary-soft-border` | `#5EEAD4` (teal-300) | |
| `--success` | `#0F766E` | **⚠ primary와 동일값** |
| `--success-soft` | `#CCFBF1` | **⚠ primary-soft와 동일값** |

- 구조: h1 직접 노출 (h1-row 없음 · 정합) → hero-line ✓
- 광고 2슬롯 · SEO·JSON-LD·CF Analytics 완비 ✓
- 2상태: waiting(teal soft) · done(하드코딩 emerald `#10b981`·`#D1FAE5`)
- done 상태 CSS에서 `--success` 토큰 미참조 → 하드코딩 emerald-600 계열 직접 사용
- 등급 테이블(1~5등급+인지지원) · 신청 절차 5단계 · 급여 그리드 완결 ✓
- favicon: 👴 + teal 배경 ✓

### 도메인 분석

노인장기요양보험을 찾는 사용자: **가족 어르신의 상태가 나빠져 요양 서비스를 받을 수 있는지 확인 중**. 복지 혜택이기도 하지만 의료적 등급 판정이라는 무게감이 앞선다.

기존 스카이블루 `#0369A1` = "교통·공공 서비스·복지 혜택"으로 확정.
요양보험도 복지이지만 — **의료적 판단·등급 심사**라는 도메인 결이 스카이블루와 다르다.

teal은 국내외 의료·헬스케어 브랜딩의 가장 보편적인 색역이다. "스카이블루 = 복지 접근 채널, teal = 의료·요양 서비스"로 축을 분리하면 나중에 병원·건강 유틸로 확장 시에도 자연스럽게 연결된다.

→ **teal `#0F766E` 현행 유지, 신규 팔레트 축 "의료·요양·건강 서비스" 편입 권고.**

### 대비값

`#0F766E` vs `#FFFFFF` ≈ **8.5:1** → AAA 통과 ✓ (이슈 없음)

### 이슈 — `--success` 토큰 미분리

`--success: #0F766E`는 `--primary`와 동일값이라 토큰이 의미 없다. 실제 done 상태는 CSS에서 이 토큰을 참조하지 않고 `#10b981`·`#059669`·`#065f46`·`#D1FAE5`를 하드코딩으로 사용 중 → 기능은 정상이지만 코드 정합이 깨져 있다.

**달리 제안 — 교체 (다빈치 판정 항목):**

| 토큰 | 현행 | 제안 |
|------|------|------|
| `--success` | `#0F766E` (= primary) | `#059669` (emerald-600 · done 상태 하드코딩과 일치) |
| `--success-soft` | `#CCFBF1` (= primary-soft) | `#D1FAE5` (done 배경 하드코딩과 일치) |

이렇게 하면 `:root` 토큰이 실제 CSS 상태와 정합되고, 향후 done 상태 색 변경 시 하드코딩 4곳을 찾지 않아도 된다.
